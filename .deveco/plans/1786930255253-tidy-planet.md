# 装饰器 V2 渐进式迁移计划

## 一、迁移背景

### 当前状态

**V1 装饰器使用统计**：
- @Component: 49 个
- @State: 46 个
- @Prop: 26 个
- @Provide: 1 个
- @Consume: 1 个
- @Builder: 91 个（保持不变）
- @BuilderParam: 5 个（保持不变）
- @Link: 1 个（保持不变）

**V2 装饰器已使用**：
- @ComponentV2: 11 个
- @Local: 21 个
- @Param: 16 个

### V2 优势

1. **性能提升**：更精确的依赖追踪，减少不必要的重新渲染
2. **语法简化**：@Local 替代 @State，@Param 替代 @Prop，语义更清晰
3. **类型安全**：更严格的类型检查，更好的编译时错误提示
4. **未来支持**：HarmonyOS NEXT 官方推荐，新特性优先支持 V2

## 二、迁移策略

### 渐进式迁移原则

1. **分阶段迁移**：按复杂度分 4 个阶段
2. **逐步验证**：每个阶段完成后进行测试验证
3. **保持稳定**：确保每个阶段都不影响现有功能
4. **文档记录**：记录迁移过程和遇到的问题

### 迁移优先级

**优先级排序**：
1. 简单组件（只使用 @Component 和 @State）- 风险低
2. 中等复杂组件（使用 @Prop）- 风险中
3. 复杂组件（使用 @Provide/@Consume）- 风险高
4. 全量测试验证

## 五、关键技术点

### 1. @Component → @ComponentV2

**迁移前**：
```typescript
@Component
struct MyComponent {
  build() {
    // ...
  }
}
```

**迁移后**：
```typescript
@ComponentV2
struct MyComponent {
  build() {
    // ...
  }
}
```

**注意**：无需其他修改

---

### 2. @State → @Local

**迁移前**：
```typescript
@Component
struct MyComponent {
  @State count: number = 0
  
  build() {
    // ...
  }
}
```

**迁移后**：
```typescript
@ComponentV2
struct MyComponent {
  @Local count: number = 0
  
  build() {
    // ...
  }
}
```

**注意**：语义更清晰，功能相同

---

### 3. @Prop → @Param

**迁移前**：
```typescript
@Component
struct ChildComponent {
  @Prop title: string = ''
  
  build() {
    Text(this.title)
  }
}

@Component
struct ParentComponent {
  build() {
    ChildComponent({ title: 'Hello' })
  }
}
```

**迁移后**：
```typescript
@ComponentV2
struct ChildComponent {
  @Param title: string = ''
  
  build() {
    Text(this.title)
  }
}

@ComponentV2
struct ParentComponent {
  build() {
    ChildComponent({ title: 'Hello' })
  }
}
```

**注意**：
- @Param 的默认值处理与 @Prop 相同
- 父组件传递参数的方式不变
- 需要确保父子组件都使用 V2 装饰器

---

### 4. @Provide/@Consume → @Provider/@Consumer

**迁移前**：
```typescript
@Component
struct ParentComponent {
  @Provide userInfo: UserInfoModel = {}
  
  build() {
    ChildComponent()
  }
}

@Component
struct ChildComponent {
  @Consume userInfo: UserInfoModel = {}
  
  build() {
    Text(this.userInfo.name)
  }
}
```

**迁移后**：
```typescript
@ComponentV2
struct ParentComponent {
  @Provider userInfo: UserInfoModel = {}
  
  build() {
    ChildComponent()
  }
}

@ComponentV2
struct ChildComponent {
  @Consumer userInfo: UserInfoModel = {}
  
  build() {
    Text(this.userInfo.name)
  }
}
```

**注意**：
- V2 的依赖注入机制更严格
- 需要确保数据流方向正确
- 可能需要调整初始化方式

---

### 5. @Builder 和 @BuilderParam

**保持不变**：
```typescript
@Builder
function myBuilder() {
  // ...
}

@ComponentV2
struct MyComponent {
  @BuilderParam contentBuilder: () => void
  
  build() {
    this.contentBuilder()
  }
}
```

**注意**：@Builder 和 @BuilderParam 在 V2 中保持不变

## 六、风险评估

### 潜在风险

| 风险 | 影响 | 概率 | 应对措施 |
|------|------|------|----------|
| 编译错误 | 高 | 低 | 逐步迁移，每步验证 |
| 运行时错误 | 高 | 中 | 充分测试，及时回滚 |
| 性能下降 | 中 | 低 | 性能测试，对比优化 |
| 类型错误 | 中 | 中 | 严格类型检查 |
| 跨组件通信失败 | 高 | 中 | 重点测试跨组件通信 |

### 回滚策略

1. **Git 分支管理**：
   - 创建 `feature/decorator-v2-migration` 分支
   - 每个阶段独立提交
   - 出现问题可以快速回滚

2. **渐进式回滚**：
   - 如果某个组件迁移失败，可以单独回滚
   - 不影响其他已迁移的组件
