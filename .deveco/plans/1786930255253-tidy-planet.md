## 二、命名规范章节内容

### 2.1 文件命名规范

#### 页面文件命名

**规范**：
- ✅ 文件名使用 PascalCase（大驼峰）
- ✅ 不添加 Page 后缀（文件夹已是 pages）
- ✅ 语义清晰，见名知意
- ❌ 避免使用缩写或简写

**示例**：
```
✅ 正确：
- Login.ets          # 登录页
- Profile.ets        # 个人中心
- WebBrowser.ets     # 网页浏览器
- NetworkComparison.ets  # 网络对比

❌ 错误：
- login.ets          # 小写
- LoginPage.ets      # 多余的 Page 后缀
- My.ets             # 语义不清
- WebPg.ets          # 缩写
```

#### 组件文件命名

**规范**：
- ✅ 使用 PascalCase
- ✅ 功能性前缀（如 Article、Project）
- ✅ 后缀表示类型（Cell、View、Header）

**示例**：
```
✅ 正确：
- ArticleCell.ets    # 文章单元格
- ProjectCell.ets    # 项目单元格
- BannerView.ets     # Banner 视图
- MyHeader.ets       # 我的页头部

❌ 错误：
- articleCell.ets    # 小写开头
- ArticleListItem.ets  # 过长
```

#### ViewModel 文件命名

**规范**：
- ✅ 页面名 + ViewModel
- ✅ 使用 PascalCase

**示例**：
```
✅ 正确：
- LoginViewModel.ets
- HomeViewModel.ets
- RankViewModel.ets
```

#### Repository 文件命名

**规范**：
- ✅ 功能名 + Repository
- ✅ 使用 PascalCase

**示例**：
```
✅ 正确：
- LoginRepository.ets
- HomeRepository.ets
- RankRepository.ets
```

### 2.2 组件命名规范

#### struct 命名

**规范**：
- ✅ 与文件名一致
- ✅ 使用 PascalCase

**示例**：
```typescript
// Profile.ets
@Entry({ routeName: RouterName.Profile })
@Component
struct Profile {  // ✅ 与文件名一致
  // ...
}

// ArticleCell.ets
@Component
export struct ArticleCell {  // ✅ 与文件名一致
  // ...
}
```

#### Builder 函数命名

**规范**：
- ✅ struct 名称 + Builder
- ✅ 用于 routerMap.json 配置

**示例**：
```typescript
// Profile.ets
@Builder
export function ProfileBuilder() {  // ✅ Profile + Builder
  Profile()
}
```

### 2.3 变量命名规范

#### 状态变量

**规范**：
- ✅ 使用 @State、@Local、@Prop 等装饰器
- ✅ 语义清晰的命名
- ✅ 布尔值使用 is/has 前缀

**示例**：
```typescript
✅ 正确：
@State isLoading: boolean = false      // 加载状态
@State hasMore: boolean = true          // 是否有更多
@State currentIndex: number = 0         // 当前索引
@State articleList: Article[] = []      // 文章列表

❌ 错误：
@State loading: boolean = false         // 缺少 is 前缀
@State list: Article[] = []             // 命名不清晰
```

#### 私有变量

**规范**：
- ✅ 使用 private 修饰符
- ✅ 不使用下划线前缀（ArkTS 不推荐）

**示例**：
```typescript
✅ 正确：
private httpClient: HttpClient = getHttpClient()
private viewModel: HomeViewModel = new HomeViewModel()

❌ 错误：
private _httpClient: HttpClient  // 不使用下划线
```

### 2.4 路由命名规范

#### RouterName 枚举

**规范**：
- ✅ 枚举名与页面名一致
- ✅ 字符串值与枚举名一致
- ✅ 使用 PascalCase

**示例**：
```typescript
export enum RouterName {
  Login = "Login",           // ✅ 一致
  Profile = "Profile",       // ✅ 一致
  WebBrowser = "WebBrowser", // ✅ 一致
  HotKey = "HotKey",         // ✅ 大小写一致
  
  // ❌ 错误示例
  Web = "WebPage",           // ❌ 不一致
  Hotkey = "HotKey",         // ❌ 大小写不一致
}
```

#### routerMap.json 配置

**规范**：
- ✅ name 与 RouterName 枚举值一致
- ✅ pageSourceFile 路径正确
- ✅ buildFunction 名称正确

**示例**：
```json
{
  "name": "Profile",                    // ✅ 与枚举一致
  "pageSourceFile": "src/main/ets/pages/Profile.ets",
  "buildFunction": "ProfileBuilder"     // ✅ 与 Builder 函数一致
}
```

## 三、HSP 模块开发章节内容

### 3.1 HSP 模块创建

#### 创建步骤

1. **创建模块目录**
```bash
# 在项目根目录创建 HSP 模块
mkdir -p network/src/main/ets
```

2. **创建配置文件**
```typescript
// network/build-profile.json5
{
  "apiType": 'stageMode',
  "buildOption": {
    "sourceOption": {
      "workers": [
        './src/main/ets/workers/TcpSocketWorker.ets'
      ]
    }
  },
  "buildOptionHar": {
    "enableBuildHar": true,  // 启用 HAR 构建
    "buildHarConfig": {
      "name": "network",     // HAR 包名称
      "version": "1.0.0"     // 版本号
    }
  }
}
```

3. **创建 oh-package.json5**
```json5
{
  "name": "network",
  "version": "1.0.0",
  "description": "网络请求模块",
  "main": "Index.ets",
  "author": "",
  "license": "ISC",
  "dependencies": {
    "@ohos/axios": "2.2.14"
  }
}
```

4. **创建 Index.ets 导出文件**
```typescript
// network/Index.ets
/**
 * Network SDK - 统一导出
 */
export * from './src/main/ets/Network';
export { getHttpClient } from './src/main/ets/Network';
```

5. **在主模块中依赖**
```json5
// entry/oh-package.json5
{
  "dependencies": {
    "network": "file:../network"
  }
}
```

### 3.4 HSP 模块最佳实践

#### 模块划分原则

1. **按功能划分**：
   - network：网络请求
   - common-ui：通用 UI 组件
   - utils：工具库
   - user：用户业务模块

2. **依赖关系**：
   - 基础模块不依赖业务模块
   - 业务模块可以依赖基础模块
   - 避免循环依赖

3. **导出规范**：
   - 统一在 Index.ets 中导出
   - 只导出必要的 API
   - 内部实现不导出

### 4.3 Repository 模式

#### 创建 Repository

```typescript
// LoginRepository.ets
import { BaseRepository, ApiError } from './base/BaseRepository'
import { ApiConstants } from '../constants/ApiConstants'
import { LoginModel } from '../model/LoginModel'

export class LoginRepository extends BaseRepository {
  /**
   * 用户登录
   */
  async login(username: string, password: string): Promise<LoginModel> {
    try {
      const response = await this.httpClient.post<LoginModel>(
        ApiConstants.userLogin(username, password)
      )
      
      // 检查错误码
      if (response.errorCode !== 0) {
        throw new Error(response.errorMsg || '登录失败')
      }
      
      return response.data
    } catch (error) {
      this.handleError(error as ApiError)
      throw error as Error
    }
  }
}
```

#### 使用 Repository

```typescript
// LoginViewModel.ets
import { LoginRepository } from '../repository/LoginRepository'

export class LoginViewModel {
  private loginRepo = new LoginRepository()
  
  async login(username: string, password: string): Promise<boolean> {
    try {
      const loginModel = await this.loginRepo.login(username, password)
      // 处理登录成功
      return true
    } catch (error) {
      // 处理错误
      return false
    }
  }
}
```

### 5.3 路由跳转

#### 基本跳转

```typescript

// 跳转到指定页面
```

### 5.4 参数传递

#### 顺传值（父→子）

```typescript
// 发送方
navPathStack.pushPath({ 
  name: RouterName.WebBrowser,
  param: { url: 'https://example.com' }
})

// 接收方
struct WebBrowser {
  aboutToAppear(): void {
    const context = getContext(this) as NavDestinationContext
    const param = context.pathInfo.param as { url: string }
    console.log(param.url)
  }
}
```

#### 逆传值（子→父）

```typescript
// 子页面
navPathStack.pop({ result: 'success', data: userInfo })

// 父页面
struct ParentPage {
  aboutToAppear(): void {
    const context = getContext(this) as NavDestinationContext
    context.pathStack.pushPath({
      name: RouterName.Login,
      onPop: (popInfo: PopInfo) => {
        // 接收返回值
        const result = popInfo.result
        console.log(result)
      }
    })
  }
}
```

### 5.5 路由拦截

#### 配置拦截器

```typescript
// navPathStack.ets
const AuthNames: string[] = [
  'MyCollect',
  'MyCoin',
  'Setting',
  'WebExample',
  'WebComponent'
]

navPathStack.setInterception({
  willShow(from, to) {
    const pageName = to.pathInfo?.name
    
    // 检查是否需要登录
    if (AuthNames.includes(pageName)) {
      if (!AccountManager.shared().isLogin()) {
        // 未登录，跳转到登录页
        to.pathStack.pop()
        to.pathStack.pushPath({ name: 'Login' })
      }
    }
  }
})
```

### 5.6 注意事项

#### ⚠️ 常见错误

1. **忘记配置 routerMap.json**
   - 现象：navPathStack.pushPath 无法跳转
   - 解决：在 routerMap.json 中添加配置

2. **忘记添加 RouterName import**
   - 现象：编译错误
   - 解决：在 RouterName.ets 中添加 import

3. **Builder 函数名称不匹配**
   - 现象：运行时错误
   - 解决：Builder 函数名 = struct 名 + Builder

4. **忘记 NavDestination 包裹**
   - 现象：页面无法正常显示
   - 解决：页面内容用 NavDestination 包裹

## 七、ArkTS 最佳实践章节内容

### 7.1 状态管理

#### @State vs @Local

```typescript
// @Component 中使用 @State
@Component
struct MyComponent {
  @State count: number = 0
}

// @ComponentV2 中使用 @Local
@ComponentV2
struct MyComponentV2 {
  @Local count: number = 0
}
```

#### @Prop vs @Link

```typescript
// @Prop：单向数据流
@Component
struct ChildComponent {
  @Prop title: string  // 父组件传入，子组件只读
}

// @Link：双向数据流
@Component
struct ChildComponent {
  @Link count: number  // 父子组件双向同步
}
```

#### @Provide/@Consume

```typescript
// 父组件提供数据
@Component
struct ParentComponent {
  @Provide userInfo: UserInfo = {}
  
  build() {
    Column() {
      ChildComponent()
    }
  }
}

// 子组件消费数据
@Component
struct ChildComponent {
  @Consume userInfo: UserInfo
  
  build() {
    Text(this.userInfo.name)
  }
}
```

### 7.4 性能优化

#### LazyForEach 使用

```typescript
// 使用 LazyForEach 优化长列表
@Component
struct MyComponent {
  @State dataList: DataItem[] = []
  
  build() {
    List() {
      LazyForEach(
        new MyDataSource(this.dataList),
        (item: DataItem) => {
          ListItem() {
            ItemView({ item: item })
          }
        },
        (item: DataItem) => item.id.toString()
      )
    }
  }
}
```

#### 避免频繁更新

```typescript
// ❌ 错误：频繁更新整个数组
this.dataList = [...this.dataList, newItem]

// ✅ 正确：使用 LazyForEach 的数据源
this.dataSource.addDataItem(newItem)
```

```typescript
function isArticle(data: Object): data is Article {
  return 'id' in data && 'title' in data
}

if (isArticle(data)) {
  // 安全使用
}
```

## 八、常见问题与调试章节内容

### 8.1 编译错误

#### arkts-no-standalone-this

**错误**：
```
ArkTS: Cannot use 'this' in standalone function
```

**原因**：在静态方法或独立函数中使用 this

**解决**：
```typescript
// ❌ 错误
static function getData() {
  return this.httpClient.get()  // this 不存在
}

// ✅ 正确
static function getData() {
  return getHttpClient().get()  // 使用全局函数
}
```

#### arkts-no-obj-literals-as-types

**错误**：
```
Object literals cannot be used as type declarations
```

**原因**：使用对象字面量作为类型

**解决**：
```typescript
// ❌ 错误
interface IAccountManager {
  loginModel?: {
    username?: string
    password?: string
  }
}

// ✅ 正确
interface ILoginModel {
  username?: string
  password?: string
}

interface IAccountManager {
  loginModel?: ILoginModel
}
```
