## 一、概述

网络缓存是提升应用性能、减少网络请求、降低服务器负载的重要手段。本文档设计一套完整的 HTTP 缓存机制，适用于 HarmonyOS 应用。

### 1.1 设计目标

1. **减少网络请求**：重复数据使用缓存，减少不必要的网络请求
2. **提升用户体验**：缓存数据可以立即展示，减少等待时间
3. **支持离线访问**：缓存数据在无网络时仍可访问
4. **灵活的缓存策略**：根据不同业务场景选择合适的缓存策略

### 1.2 缓存类型

| 类型 | 说明 | 生命周期 |
|------|------|----------|
| 内存缓存 | 保存在内存中 | 应用关闭后失效 |
| 磁盘缓存 | 保存在磁盘中 | 持久化存储 |

## 二、缓存策略

### 2.1 策略类型

```typescript
enum CacheStrategy {
  /** 不缓存 - 每次请求都从网络获取 */
  NO_CACHE = 'no_cache',

  /** 仅内存缓存 - 仅缓存在内存中 */
  MEMORY_ONLY = 'memory_only',

  /** 仅磁盘缓存 - 仅缓存在磁盘中 */
  DISK_ONLY = 'disk_only',

  /** 缓存优先 - 先使用缓存，失败时请求网络 */
  CACHE_FIRST = 'cache_first',

  /** 网络优先 - 先请求网络，失败时使用缓存 */
  NETWORK_FIRST = 'network_first',

  /** 后台更新 - 使用缓存同时在后台更新数据 */
  STALE_WHILE_REVALIDATE = 'stale_while_revalidate'
}
```

### 2.2 策略选择建议

| 场景 | 推荐策略 | 原因 |
|------|----------|------|
| 文章列表 | CACHE_FIRST | 数据变化不频繁，可接受一定延迟 |
| 搜索结果 | NO_CACHE | 数据实时性要求高 |
| 用户收藏 | NETWORK_FIRST | 数据变化需及时反映 |
| 首页 Banner | CACHE_FIRST | 变化不频繁，需要快速展示 |
| 排行榜 | STALE_WHILE_REVALIDATE | 需要快速展示但也要保持新鲜 |
| 详情页 | CACHE_FIRST | 数据变化不频繁 |

### 2.3 流程图

#### 缓存优先策略 (CACHE_FIRST)

```
发起请求
    │
    ▼
检查缓存是否存在？
    │
    ├── 是 ──► 检查是否过期？
    │              │
    │              ├── 未过期 ──► 返回缓存数据
    │              │
    │              └── 已过期 ──► 请求网络
    │                            │
    │                     更新缓存
    │                            │
    │                     返回新数据
    │
    └── 否 ──► 请求网络
                   │
            更新缓存
                   │
            返回新数据
```

#### 后台更新策略 (STALE_WHILE_REVALIDATE)

```
发起请求
    │
    ▼
检查缓存是否存在？
    │
    ├── 是 ──► 立即返回缓存数据
    │          同时发起后台更新请求
    │                     │
    │              更新缓存
    │
    └── 否 ──► 请求网络
                   │
            返回新数据
```

## 三、缓存配置

### 3.1 配置接口

```typescript
interface CacheConfig {
  /** 缓存策略 */
  strategy: CacheStrategy
  /** 缓存有效期（秒） */
  maxAge: number
  /** 后台更新延迟（秒） */
  staleWhileRevalidate?: number
}
```

### 3.2 预定义配置

```typescript
class CacheConfigFactory {
  /** 默认缓存配置 - 5 分钟缓存 */
  static readonly DEFAULT: CacheConfig = {
    strategy: CacheStrategy.CACHE_FIRST,
    maxAge: 300
  }

  /** 短缓存配置 - 1 分钟 */
  static readonly SHORT: CacheConfig = {
    strategy: CacheStrategy.CACHE_FIRST,
    maxAge: 60
  }

  /** 长缓存配置 - 30 分钟 */
  static readonly LONG: CacheConfig = {
    strategy: CacheStrategy.CACHE_FIRST,
    maxAge: 1800
  }

  /** 不缓存配置 */
  static readonly NO_CACHE: CacheConfig = {
    strategy: CacheStrategy.NO_CACHE,
    maxAge: 0
  }
}
```

## 四、缓存管理器

### 4.1 核心功能

```typescript
class HttpCacheManager {
  // 设置缓存
  set(key: string, data: object, config: CacheConfig): void

  // 获取缓存
  get<T>(key: string): T | null

  // 检查是否过期
  isExpired(key: string): boolean

  // 移除缓存
  remove(key: string): void

  // 清除所有缓存
  clear(): void

  // 获取缓存数量
  getCacheCount(): number

  // 生成缓存键
  static generateKey(url: string, params?: object): string
}
```

### 4.2 缓存键生成规则

```typescript
// 缓存键 = URL + 参数的 JSON 序列化
const key = `${url}_${JSON.stringify(params)}`

// 示例
// GET /article/list?page=1&size=10
// 缓存键: "/article/list_{"page":1,"size":10}"
```

## 五、BaseProvider 集成

### 5.1 集成方式

修改 BaseProvider 的 get 和 post 方法，支持可选的缓存配置：

```typescript
protected get<T>(
  path: string,
  config?: AxiosRequestConfig,
  cacheConfig?: CacheConfig
): Promise<AxiosResponse>

protected post<T>(
  path: string,
  data?: object,
  config?: AxiosRequestConfig,
  cacheConfig?: CacheConfig
): Promise<AxiosResponse>
```

### 5.2 使用示例

```typescript
// 使用默认缓存配置（5分钟）
const articles = await this.get<Article[]>('/article/list')

// 使用短缓存（1分钟）
const hotNews = await this.get<News[]>(
  '/news/hot',
  undefined,
  CacheConfigFactory.SHORT
)

// 不使用缓存
const searchResults = await this.get<Result[]>(
  '/search',
  { params: { keyword: 'HarmonyOS' } },
  CacheConfigFactory.NO_CACHE
)

// 后台更新策略
const banner = await this.get<Banner[]>(
  '/banner',
  undefined,
  CacheConfigFactory.STALE_WHILE_REVALIDATE
)
```

## 六、存储实现

### 6.1 内存缓存

使用 Map 数据结构存储，适合小量数据：

```typescript
private memoryCache: Map<string, CacheItem> = new Map()
```

### 6.2 磁盘缓存

使用 HarmonyOS 的用户首选项 (Preferences)：

```typescript
import { dataPreferences } from '@kit.ArkData'

// 获取实例
const prefs = dataPreferences.getPreferencesSync(context, {
  name: 'http_cache'
})

// 存储
prefs.putSync('cache_key', JSON.stringify(cacheItem))
prefs.flush()

// 读取
const value = prefs.getSync('cache_key', '')
// 删除
prefs.deleteSync('cache_key')
```

## 七、缓存清理策略

### 7.1 主动清理

- POST 请求成功后清除相关缓存（列表页缓存）
- 用户主动刷新时清除缓存
- 退出登录时清除用户相关缓存

### 7.2 被动清理

- 缓存过期自动失效
- 应用启动时检查并清理过期缓存
- 缓存数量超过阈值时清理最旧缓存

### 7.3 清理时机

| 场景 | 清理操作 |
|------|----------|
| 用户登录/登出 | 清除所有用户相关缓存 |
| 收藏/取消收藏 | 清除收藏列表缓存 |
| 发布文章 | 清除首页列表缓存 |
| 应用启动 | 检查并清理过期缓存 |

## 八、最佳实践

### 8.1 缓存键设计

- 使用有意义的键名
- 包含请求参数
- 考虑参数的顺序无关性

### 8.2 缓存时间设置

| 数据类型 | 建议缓存时间 |
|----------|--------------|
| 用户信息 | 30 分钟 - 1 小时 |
| 列表数据 | 5 - 15 分钟 |
| 详情数据 | 15 - 30 分钟 |
| 搜索结果 | 不缓存 |
| 静态配置 | 1 - 24 小时 |

### 8.3 错误处理

- 网络失败时回退到缓存
- 缓存解析失败时删除缓存
- 存储空间不足时清理旧缓存
