## 一、概述

离线数据持久化是提升应用体验的重要手段，允许用户在无网络或网络不佳的情况下仍能访问已缓存的数据。本文档设计一套完整的离线数据方案。

### 1.1 设计目标

1. **支持离线访问**：在无网络时仍能查看已缓存的文章和收藏
2. **数据同步机制**：确保本地数据与远端数据的一致性
3. **统一的数据访问层**：提供清晰的数据接口，屏蔽底层存储细节
4. **离线操作队列**：支持离线时的操作，待网络恢复后自动同步

### 1.2 核心组件

```
┌─────────────────────────────────────────────────────────────┐
│                      ArticleRepository                        │

└──────────────────────────┬──────────────────────────────────┘
                           │
```

## 二、数据仓储层 (Repository)

### 2.1 职责

- 统一管理数据的获取来源（网络/本地）
- 实现数据同步逻辑
- 提供离线优先的访问模式
- 屏蔽底层存储细节

### 2.2 核心接口

```typescript
class ArticleRepository {
  // 获取文章列表（优先本地，失败时请求网络）
  async getArticles(page: number, forceRefresh?: boolean): Promise<Article[]>

  async getCollections(): Promise<Article[]>

  // 收藏文章
  async collectArticle(articleId: number): Promise<boolean>

  // 取消收藏
  async uncollectArticle(articleId: number): Promise<boolean>

  // 同步收藏
  async syncCollections(): Promise<void>
}
```

### 2.3 离线优先策略

```typescript
async getArticles(page: number, forceRefresh: boolean = false): Promise<Article[]> {
  // 1. 如果强制刷新或本地无数据，先尝试网络
  if (forceRefresh || localData.length === 0) {
    try {
      const networkData = await fetchFromNetwork()
      await saveToLocal(networkData)
      return networkData
    } catch (error) {
      // 网络失败，回退到本地
    }
  }

  // 2. 返回本地数据
  return localData
}
```

## 三、本地存储层 (LocalStore)

### 3.1 存储选型

| 存储方式 | 适用场景 | 优点 | 缺点 |
|----------|----------|------|------|
| 用户首选项 (Preferences) | 少量键值数据 | 轻量、简单 | 不适合大量数据 |
| 关系型数据库 (RDB) | 结构化数据 | SQL 查询能力 | 配置复杂 |
| 分布式数据库 (Distributed) | 跨设备同步 | 支持分布式 | 需要网络 |

**选择**：使用用户首选项存储文章数据，原因：
- 数据量适中（文章列表通常 < 1000 条）
- 实现简单快速
- 满足当前需求

## 四、数据同步策略

### 4.1 同步时机

| 操作 | 同步策略 |
|------|----------|
| 打开收藏页 | 后台同步，显示本地数据 |
| 收藏文章 | 先本地，后台同步远端 |
| 取消收藏 | 先本地，后台同步远端 |
| 下拉刷新 | 强制刷新，同步最新数据 |
| 应用启动 | 可选：后台同步 |

### 4.2 同步流程

```
用户操作：收藏文章
    │
    ▼
1. 保存到本地 ──► 显示操作成功
    │
    ▼
2. 发送到远端
    │
    ├── 成功 ──► 更新同步状态
    │
    └── 失败 ──► 加入重试队列
```

### 4.3 冲突处理

当本地数据与远端数据不一致时：
- **收藏列表**：以远端数据为准（权威数据源）
- **文章列表**：保留最新获取的数据
- **操作冲突**：记录冲突，待用户确认

## 五、离线操作队列

### 5.1 待同步操作

```typescript
interface PendingOperation {
  id: string
  type: 'collect' | 'uncollect'
  articleId: number
  timestamp: number
  retryCount: number
}
```

### 5.2 同步机制

```typescript
class OfflineQueue {
  private queue: PendingOperation[] = []

  // 添加操作到队列
  add(operation: PendingOperation): void {
    this.queue.push(operation)
    this.persist() // 持久化
  }

  // 执行同步
  async sync(): Promise<void> {
    for (const op of this.queue) {
      try {
        await this.execute(op)
        this.remove(op.id)
      } catch (error) {
        op.retryCount++
        if (op.retryCount >= 3) {
          // 超过重试次数，标记失败
          this.markFailed(op.id)
        }
      }
    }
  }
}
```

## 七、最佳实践

### 7.1 缓存策略

| 数据类型 | 缓存时间 | 同步策略 |
|----------|----------|----------|
| 首页文章 | 5-15 分钟 | 后台更新 |
| 收藏列表 | 实时同步 | 前台同步 |
| 文章详情 | 30 分钟 | 按需加载 |
| 用户信息 | 1 小时 | 后台同步 |

### 7.2 存储限制

- 单次存储不超过 1MB
- 收藏列表不超过 500 条
- 超过限制时清理旧数据

### 7.3 错误处理

```typescript
async getArticles(): Promise<Article[]> {
  try {
    return await fetchFromNetwork()
  } catch (networkError) {
    // 网络失败，尝试本地
    const localData = await localStore.getArticles()
    if (localData.length > 0) {
      // 返回本地数据，但提示用户
      showToast('当前为离线模式')
      return localData
    }
    // 本地也没有，抛出错误
    throw new Error('无网络且本地无缓存')
  }
}
```
