## 一、选择题高频考点

### 1.1 ArkUI 状态管理

#### 考点1: @State vs @Prop vs @Link 区别

**题目**: 以下关于状态管理装饰器的说法，正确的是？

A. @State 变量可以从父组件传递
B. @Prop 变量可以在子组件中修改
C. @Link 变量在子组件中修改会影响父组件
D. @State 和 @Link 可以互相替代

**答案**: C

**解析**:
- @State 是组件私有，只能组件内部使用
- @Prop 是父到子单向传递，子组件不能直接修改
- @Link 是双向绑定，子组件修改会影响父组件

---

#### 考点2: @Observed 和 @ObjectLink

**题目**: 使用 @ObjectLink 时，正确的做法是？

A. @Observed 装饰在组件上
B. @ObjectLink 装饰在类上
C. @Observed 装饰在自定义类上
D. @Observed 装饰在 @ObjectLink 变量上

**答案**: C

**解析**:
- @Observed 装饰在自定义类上，标记类需要被观察
- @ObjectLink 装饰在组件变量上，引用被 @Observed 装饰的类

---

#### 考点3: AppStorage vs LocalStorage

**题目**: 页面级别的状态存储应该使用？

A. AppStorage
B. LocalStorage
C. 两者都可以
D. 两者都不行

**答案**: B

**解析**:
- AppStorage 是应用级全局存储，生命周期与应用相同
- LocalStorage 是页面级存储，页面关闭后自动清除

### 1.2 生命周期

#### 考点4: Ability 生命周期顺序

**题目**: Ability 启动时，生命周期的正确顺序是？

A. onCreate → onForeground → onWindowStageCreate
B. onCreate → onWindowStageCreate → onForeground
C. onWindowStageCreate → onCreate → onForeground
D. onCreate → onWindowStageDestroy → onDestroy

**答案**: B

**解析**:
1. onCreate - Ability 创建
2. onWindowStageCreate - 窗口创建（加载页面内容）
3. onForeground - 进入前台

---

#### 考点5: aboutToAppear vs build

**题目**: 以下哪个操作在 aboutToAppear 中可以执行？

A. 修改 @State 变量
B. 调用 router 方法
C. 执行网络请求
D. 上述都可以

**答案**: D

**解析**:
- aboutToAppear 在 build 之前调用，可以进行数据初始化
- build 中不应该调用 setState，这会触发无限循环

### 1.3 网络请求

#### 考点6: 拦截器执行顺序

**题目**: 有两个请求拦截器 R1 和 R2（R1 先注册），执行顺序是？

A. R1 → R2 → 请求 → R2 → R1 → 响应
B. R2 → R1 → 请求 → R1 → R2 → 响应
C. R1 → R2 → 请求 → 响应 → R1 → R2
D. 按注册顺序依次执行

**答案**: A

**解析**:
- 请求拦截：按注册顺序执行
- 响应拦截：按注册顺序倒序执行

#### 考点7: 缓存策略选择

**题目**: 首页 Banner 适合使用哪种缓存策略？

A. NO_CACHE
B. CACHE_FIRST
C. NETWORK_FIRST
D. STALE_WHILE_REVALIDATE

**答案**: D

**解析**:
- STALE_WHILE_REVALIDATE 返回旧数据同时后台更新
- Banner 变化不频繁但需要快速展示
- 适合需要快速响应又要保持新鲜的场景

### 1.4 分布式

#### 考点8: 分布式数据库特点

**题目**: 分布式数据库的特点不包括？

A. 支持跨设备同步
B. 需要网络连接
C. 支持 SQL 查询
D. 自动冲突处理

### 1.5 安全

#### 考点10: SHA256 特点

**题目**: SHA256 哈希算法的特点不包括？

A. 单向不可逆
B. 固定输出长度
C. 适合加密存储密码
D. 可以解密还原

**答案**: D

**解析**:
- SHA256 是哈希算法，不是加密算法
- 不能逆向解密，只能暴力穷举
- 常用于签名验证

## 二、场景分析题

### 2.1 列表性能优化场景

**问题**: 首页文章列表滚动卡顿，如何优化？

**答案要点**:
1. 将 ForEach 替换为 LazyForEach
2. 设置合理的 cachedCount
3. 使用 @Reusable 装饰器
4. 避免在 build 中创建新对象
5. 使用 GPU 加速属性（transform、opacity）

---

### 2.2 跨设备数据同步场景

**问题**: 用户在手机上收藏文章，如何同步到平板？

**答案要点**:
1. 使用 DistributedDataManager
2. 定义数据同步格式
3. 选择目标设备
4. 处理数据合并和冲突
5. 提供离线队列

---

### 2.3 登录验证场景

**问题**: 如何实现需要登录才能访问的页面？

**答案要点**:
1. 使用路由守卫机制
2. LoginGuard 检查登录状态
3. 未登录重定向到登录页
4. 登录成功后继续原页面
5. 使用 AppStorage 存储登录状态

## 四、易错点总结

### 4.1 状态管理

| 易错点 | 正确做法 |
|--------|----------|
| @State 赋值不触发更新 | 使用 this.state = newValue 赋值 |
| @Prop 修改变量 | 不应该修改，只能接收 |
| @Link 缺少 @State | 父组件需要 @State |
| build 中调用 setState | 会导致无限循环 |

### 4.2 生命周期

| 易错点 | 正确做法 |
|--------|----------|
| aboutToDisappear 中未清理定时器 | 记得 clearInterval |
| 定时器未清理导致内存泄漏 | 生命周期结束时清理 |
| 网络请求在 build 中 | 应在 aboutToAppear 中 |

### 4.3 分布式

| 易错点 | 正确做法 |
|--------|----------|
| 设备不在线时同步 | 检查 isOnline 属性 |
| 忽略冲突处理 | 实现 merge 策略 |
| 大数据同步 | 分批同步 |
