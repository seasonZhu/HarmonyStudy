### 错题 #1: 请求重试机制位置

**题目**: 在封装 HTTP 请求时，请求失败后的重试逻辑应该放在哪个位置？

**选项**:
- A. 请求拦截器
- B. 响应拦截器
- C. 业务代码中
- D. 单独的重试工具类

**正确答案**: A

**我的答案**: B

**错误原因**:
对拦截器职责理解不清。请求拦截器在发送请求前被调用，适合放置重试逻辑，可以在重试前修改请求配置。

**正确理解**:
- **请求拦截器**：在请求发送前调用，可以修改配置、添加重试逻辑
- **响应拦截器**：在接收响应后调用，主要用于数据转换、错误处理

**相关代码**:

```typescript
// 请求拦截器中实现重试
this.instance.interceptors.request.use(
  async (config) => {
    // 重试计数器
    let retryCount = 0
    const maxRetries = 3

    // 发送请求，失败时重试
    while (retryCount < maxRetries) {
      try {
        return await this.executeRequest(config)
      } catch (error) {
        retryCount++
        if (retryCount >= maxRetries) {
          throw error
        }
        // 等待后重试
        await this.delay(1000 * retryCount)
      }
    }
  },
  (error) => error
)

// 响应拦截器用于数据处理
this.instance.interceptors.response.use(
  (response) => {
    return response.data
  },
  (error) => {
    // 统一错误处理，不做重试
    return Promise.reject(error)
  }
)
```

**涉及知识点**:
- 网络请求拦截器
- Axios 拦截器执行顺序
- 重试机制设计

### 错题 #2: @State 变量修改时机

**题目**: 以下关于 @State 变量的说法，错误的是？

**选项**:
- A. 可以在 aboutToAppear 中修改
- B. 可以在 build 中修改
- C. 可以在点击事件回调中修改
- D. 修改后会触发 UI 重新渲染

**正确答案**: B

**解析**:
- aboutToAppear 在 build 之前调用，可以修改 @State
- build 中不应该调用 setState，这会导致无限循环
- 点击事件回调中可以修改

**错误代码示例**:

```typescript
// 错误：在 build 中修改 @State
build() {
  this.counter++  // 错误！会导致无限循环

  Column() {
    Text(this.counter.toString())
  }
}

// 正确：在事件处理中修改
build() {
  Column() {
    Text(this.counter.toString())
    Button('增加')
      .onClick(() => {
        this.counter++  // 正确
      })
  }
}
```

### 错题 #3: 分布式数据冲突处理

**题目**: 两个设备同时修改同一篇文章的收藏状态，分布式数据同步时应该？

**选项**:
- A. 以最后修改为准
- B. 保留两个版本
- C. 抛出冲突异常
- D. 合并冲突数据

**正确答案**: A

**解析**:
- 分布式数据同步通常采用"最后修改为准"(Last-Write-Wins)策略
- 可以结合时间戳判断
- 如果需要保留历史，可以采用版本向量

**实现示例**:

```typescript
// 冲突处理策略：Last-Write-Wins
function resolveConflict(local: Article, remote: Article): Article {
  // 以时间戳为准
  if (local.timestamp > remote.timestamp) {
    return local
  }
  return remote
}

// 或者使用版本向量
interface VersionVector {
  [deviceId: string]: number
}

function resolveWithVersion(local: Article, remote: Article): Article {
  // 比较版本向量
  if (isNewer(local.version, remote.version)) {
    return local
  }
  return remote
}
```
