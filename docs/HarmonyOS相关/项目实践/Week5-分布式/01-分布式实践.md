## 一、概述

分布式能力是 HarmonyOS 的核心特性之一，允许应用在不同设备间协同工作，提供跨设备的一致体验。

### 1.1 分布式能力类型

| 能力 | 说明 | 应用场景 |
|------|------|----------|
| 设备发现 | 发现同局域网内的设备 | 多设备协同 |
| 跨设备迁移 | 将任务迁移到其他设备 | 断点续传 |
| 分布式数据 | 跨设备数据同步 | 数据共享 |
| 任务调度 | 跨设备协同计算 | 性能提升 |

### 1.2 前提条件

1. 设备在同一局域网内
2. 设备登录相同的华为账号
3. 应用已申请相关权限

## 三、跨设备迁移

### 3.1 迁移 vs 流转

| 特性 | 迁移 (Migration) | 流转 (Continuation) |
|------|------------------|---------------------|
| 数据传输 | 完整数据 | 页面状态 |
| 目标设备 | 任意可信设备 | 同一应用实例 |
| 场景 | 断点续传、继续任务 | 接续操作 |
| 实现难度 | 较复杂 | 较简单 |

### 3.2 迁移流程

```
1. 源设备发起迁移请求
2. 选择目标设备
3. 打包迁移数据
4. 传输数据到目标设备
5. 目标设备恢复状态
6. 源设备结束任务
```

### 3.3 实现示例

```typescript
import { continueMission } from '@kit.DistributedScheduleKit'

// 发起迁移
async function migrateTask(taskData: TaskData): Promise<void> {
  try {
    await continueMission({
      srcDeviceId: 'source_device_id',
      dstDeviceId: 'target_device_id',
      want: {
        bundleName: 'com.huawei.harmonystudy',
        abilityName: 'EntryAbility'
      },
      params: {
        taskData: taskData
      }
    })
  } catch (error) {
    console.error('Migration failed:', error)
  }
}
```

## 四、分布式数据同步

### 4.1 数据同步策略

| 策略 | 说明 | 适用场景 |
|------|------|----------|
| 即时同步 | 数据变化立即同步 | 收藏、设置 |
| 定时同步 | 定时批量同步 | 日志、统计数据 |
| 按需同步 | 需要时同步 | 大文件 |

### 4.2 收藏同步方案

```typescript
class CollectionSyncManager {
  private dataManager: DistributedDataManager

  /**
   * 同步收藏到目标设备
   */
  async syncCollections(targetDeviceId: string): Promise<boolean> {
    // 1. 获取本地收藏
    const collections = await ArticleRepository.getInstance().getCollections()

    // 2. 序列化为 JSON
    const data = JSON.stringify(collections)

    // 3. 通过分布式数据接口同步
    await this.dataManager.syncData(targetDeviceId, {
      type: 'collections',
      data: data,
      timestamp: Date.now()
    })

    return true
  }

  /**
   * 从目标设备接收同步数据
   */
  async receiveCollections(sourceDeviceId: string): Promise<void> {
    const syncData = await this.dataManager.receiveData(sourceDeviceId)

    if (syncData && syncData.type === 'collections') {
      const collections = JSON.parse(syncData.data)

      // 合并数据（保留最新的）
      await this.mergeCollections(collections)
    }
  }

  /**
   * 合并收藏数据
   */
  private async mergeCollections(remoteCollections: Article[]): Promise<void> {
    const localCollections = await ArticleLocalStore.getInstance().getCollections()

    // 合并策略：以 remote 为准，保留本地的 extraIsCollected 状态
    const merged = remoteCollections.map(remote => {
      const local = localCollections.find(c => c.id === remote.id)
      return {
        ...remote,
        extraIsCollected: local?.extraIsCollected ?? true
      }
    })

    // 保存合并后的数据
    await ArticleLocalStore.getInstance().saveCollections(merged)
  }
}
```

### 4.3 冲突处理

| 冲突类型 | 处理策略 |
|----------|----------|
| 同时修改 | 以时间戳最新为准 |
| 删除冲突 | 保留未删除版本 |
| 数据丢失 | 从其他设备恢复 |

## 六、最佳实践

### 6.1 设备选择

```typescript
interface DeviceSelectionCriteria {
  online: boolean           // 必须在线
  sameAccount: boolean      // 同账号
  deviceType?: number[]     // 设备类型过滤
  networkType?: string[]   // 网络类型过滤
}

function selectBestDevice(devices: DeviceInfo[]): DeviceInfo | null {
  return devices
    .filter(d => d.online && d.sameAccount)
    .sort((a, b) => {
      // 优先选择同类型设备
      if (a.deviceType === b.deviceType) {
        // 再按设备名称排序
        return a.deviceName.localeCompare(b.deviceName)
      }
      return 0
    })[0] || null
}
```

### 6.2 错误处理

```typescript
async function withRetry<T>(
  operation: () => Promise<T>,
  maxRetries: number = 3
): Promise<T> {
  let lastError: Error

  for (let i = 0; i < maxRetries; i++) {
    try {
      return await operation()
    } catch (error) {
      lastError = error

      // 设备离线等错误，重试可能有效
      if (isRetryableError(error)) {
        await delay(1000 * (i + 1))  // 指数退避
        continue
      }

      throw error
    }
  }

  throw lastError!
}
```
