## 1. 分布式架构概述

### 1.1 什么是 HarmonyOS 分布式架构

HarmonyOS 分布式架构是华为鸿蒙系统的核心技术能力，旨在打破单一设备的算力边界，实现设备间的**硬件互助、资源共享**。

```
┌─────────────────────────────────────────────────────────────┐
│                    HarmonyOS 分布式架构                       │
├─────────────────────────────────────────────────────────────┤
│                                                             │
│   ┌─────────┐    ┌─────────┐    ┌─────────┐    ┌─────────┐ │
│   │  手机   │◄──►│  平板   │◄──►│  手表   │◄──►│  电视   │ │
│   └────┬────┘    └────┬────┘    └────┬────┘    └────┬────┘ │
│        │              │              │              │       │
│        └──────────────┴──────────────┴──────────────┘       │
│                              │                               │
│                     ┌────────▼────────┐                     │
│                     │   分布式软总线    │                     │
│                     │  (SoftBus)      │                     │
│                     └─────────────────┘                     │
└─────────────────────────────────────────────────────────────┘
```

### 1.2 分布式架构设计原则

| 原则 | 说明 |
|-----|------|
| **硬件互助** | 设备间能力互补，如手机调用平板摄像头 |
| **资源共享** | 打破数据孤岛，实现跨设备数据访问 |
| **算力协同** | 任务可流转到更高算力设备执行 |
| **体验连续** | 用户操作可在设备间无缝切换 |

## 2. 核心概念

### 2.1 分布式软总线 (SoftBus)

分布式软总线是 HarmonyOS 分布式能力的根基，负责：
- **设备发现**：自动发现周围可信设备
- **设备连接**：建立安全的数据通道
- **数据传输**：统一的可靠传输协议

```
┌─────────────────────────────────────────────────┐
│                 分布式软总线架构                   │
├─────────────────────────────────────────────────┤
│                                                 │
│  应用层 ────►  服务层 ────►  软总线适配层         │
│                              │                  │
│                    ┌─────────┼─────────┐        │
│                    ▼         ▼         ▼        │
│               WiFi(P2P)   BT      USB           │
│                                                 │
└─────────────────────────────────────────────────┘
```

**核心特性**：
- 自动组网：设备碰一碰、扫码等方式快速连接
- 零等待发现：近场设备毫秒级发现
- 低时延传输：局域网内时延 < 10ms

### 2.2 设备虚拟化

将物理设备的能力虚拟化为可共享的资源：

| 虚拟化类型 | 示例 | 应用场景 |
|-----------|------|---------|
| 摄像头虚拟化 | 手机使用平板大屏作为取景器 | 拍照预览 |
| 屏幕虚拟化 | 手机应用流转到平板大屏显示 | 多屏协同 |
| 音频虚拟化 | 手机音频路由到音箱播放 | 音乐共享 |
| GPS 虚拟化 | 合并多设备定位提高精度 | 导航优化 |

### 2.3 跨设备资源访问

HarmonyOS 提供了统一的 API 访问跨设备资源：

```typescript
// 跨设备文件访问
import { distributedFile } from '@kit.CoreFileKit';

// 访问远端设备的文件
const remoteFile = distributedFile.listvoyageFileSync(deviceId, '/data');
```

## 4. 应用场景分析

### 4.1 本项目可应用场景

根据项目架构分析（MVVM + BaseProvider + Router），以下场景可应用分布式能力：

#### 场景一：收藏跨设备同步

```
┌─────────┐ 收藏文章 ┌─────────┐  自动同步  ┌─────────┐
│  手机   │ ──────► │ 服务器  │ ────────► │  平板   │
└─────────┘         └─────────┘           └─────────┘
```

**技术方案**：
- 使用分布式 KV 存储收藏列表
- 用户登录后自动同步到分布式数据库
- 其他设备上线时拉取最新收藏

#### 场景二：阅读历史跨设备同步

```
┌─────────┐ 阅读文章 ┌─────────┐  上报进度  ┌─────────┐
│  手机   │ ──────► │ 服务器  │ ────────► │  平板   │
│         │         │         │  检查进度  │         │
│         │ ◄────── │         │ ◄──────── │         │
└─────────┘ 同步进度 └─────────┘           └─────────┘
```

**技术方案**：
- 阅读时上报当前进度到服务端
- 其他设备打开同一文章时检查服务器进度
- 提供"是否同步进度"的用户选择

#### 场景三：登录态跨设备共享

```
┌─────────┐ 扫码登录 ┌─────────┐  Token同步 ┌─────────┐
│  手机   │ ──────► │  平板   │ ────────► │   PC    │
└─────────┘         └─────────┘           └─────────┘
```

**技术方案**：
- 使用分布式 DataStore 加密存储 Token
- 同一网络下设备自动发现并同步登录态
- Token 刷新时自动同步到所有设备

### 4.2 场景优先级建议

| 优先级 | 场景 | 复杂度 | 价值 |
|-------|------|-------|------|
| P0 | 收藏跨设备同步 | 中 | 高 |
| P1 | 阅读进度同步 | 低 | 中 |
| P2 | 登录态跨设备共享 | 高 | 中 |

## 5. 技术限制与注意事项

### 5.1 分布式能力使用限制

| 限制项 | 说明 |
|-------|------|
| **设备要求** | 必须是 HarmonyOS 设备，且在可信设备列表中 |
| **网络要求** | 需在同一局域网或开启蓝牙发现 |
| **数据量限制** | 迁移数据建议 < 1MB |
| **权限要求** | 需要用户授权"设备间互通"权限 |
| **场景限制** | 某些场景需同账号、同局域网 |

### 5.2 调试注意事项

1. **模拟器限制**：分布式能力需要真实设备测试
2. **设备配对**：首次使用需完成设备配对和授权
3. **数据序列化**：迁移数据需实现 Serializable
4. **网络稳定性**：建议在稳定网络环境下测试
