## 自问自答

Q1: 什么情况下使用跨设备迁移而不是分布式任务调度？
A: 迁移适用于需要用户连续操作场景（如文档编辑）

Q2: 迁移的数据量有限制吗？
A: 有，一般限制在 KB 级别
   大数据需要通过分布式数据库中转

### Task 3: 专项突破 - 状态管理

**Files:**
- Create: `docs/认证备考/Week1-查漏补缺/专项02-状态管理突破.md`

- [ ] **Step 1: 整理状态装饰器对比**

```markdown
## 状态装饰器对比

| 装饰器 | 用途 | 传递方式 | 共享 |
|--------|------|---------|------|
| @State | 组件内状态 | - | 否 |
| @Prop | 父到子单向 | 拷贝 | 否 |
| @Link | 父到子双向 | 引用 | 否 |
| @Provide | 祖先到后代 | - | 是 |
| @Consume | 响应 @Provide | - | 是 |
| @StorageLink | AppStorage | - | 是 |
| @ObjectLink | 对象引用 | - | 是 |
```

- [ ] **Step 2: @Observed/@ObjectLink 原理**

```markdown
## @Observed/@ObjectLink 原理

// @Observed 装饰类
@Observed
class Article {
  id: string
  title: string
  author: Author  // 嵌套对象也需要 @Observed
}

// @ObjectLink 装饰属性
@ObjectLink article: Article

// 原理：
// 1. @Observed 标记类为可观测
// 2. 当嵌套对象变化时，通知UI刷新
// 3. @ObjectLink 建立双向绑定
```

@Observed

  address: Address

  city: string

@Component
struct Parent {
  @State user: User = new User()

```markdown
# 高频考点速记版

## ArkUI 状态管理
- @State：组件私有，适合简单值
- @Prop：单向传递，父到子
- @Link：双向绑定，父到子引用
- @Observed：让类可被观测
- @ObjectLink：配合 @Observed 使用

## 生命周期
- Ability: onCreate -> onWindowStageCreate -> onForeground -> onBackground -> onDestroy
- 页面: aboutToAppear -> build -> aboutToDisappear

## 分布式
- 迁移 = 状态迁移 + 界面迁移
- 流转 = 纯任务流转，不迁移UI
- 迁移数据量：KB级别

## 性能优化
- LazyForEach > ForEach（大列表）
- @Reusable 减少创建开销
- 减少 build() 中的对象创建
```
