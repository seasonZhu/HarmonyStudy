## 一、ArkUI 状态管理（核心重点）

### 装饰器对比速记表

```
@State      → 组件私有，简单值
@Prop       → 单向拷贝，父到子（子变父不变）
@Link       → 双向绑定，引用传递（子变父变）
@Observed   → 让类可被观测（嵌套对象也要装饰）
@ObjectLink → 配合@Observed，建立引用绑定
@Provide    → 祖先向后代提供数据
@Consume    → 响应@Provide的数据
@StorageLink → AppStorage双向同步
```

### @Observed/@ObjectLink 原理
```
@Observed 标记类 → 属性变化可被检测
@ObjectLink 建立引用 → 嵌套对象变化触发UI更新
注意：嵌套对象也必须 @Observed 装饰
```

### @ObservedV2 新特性
```
@ObservedV2 + @Trace → 新一代状态管理
自动追踪嵌套对象，无需手动处理
```

## 二、生命周期（高频）

### Ability 生命周期
```
onCreate → onWindowStageCreate → onForeground → onBackground → onDestroy
(创建)        (窗口创建)           (前台)         (后台)          (销毁)
```

### 页面生命周期
```
aboutToAppear → build → aboutToDisappear
(显示前)        (渲染)    (销毁前)
```

### 父子组件生命周期
```
父 aboutToAppear → 父 build → 子 aboutToAppear → 子 build → 子 aboutToDisappear → 父 aboutToDisappear
```

## 三、分布式能力

### 迁移 vs 流转
```
迁移(continuation) → 迁移UI + 数据，KB级别，文档/视频编辑
流转(TaskFlow)     → 只流转任务，无UI限制，后台下载
```

### 分布式数据库
```
最终一致性（非实时）
多设备自动同步
适合跨设备数据共享
```

### 软总线
```
设备间通信基础
屏蔽底层通信差异
```

## 四、性能优化

### ForEach vs LazyForEach
```
小列表(<50项) → ForEach
大列表(≥50项) → LazyForEach（按需渲染）
```

### @Reusable
```
组件实例复用
减少创建/销毁开销
配合LazyForEach效果最佳
```

### build() 优化
```
避免在build()中创建对象
减少重复计算
使用本地变量缓存
```

## 五、安全与权限

### 权限等级
```
Normal      → 静态声明即可（网络）
Restricted  → 静态+运行时申请（位置）
Grantable   → 用户动态授权（通讯录）
System      → 系统应用专用
```

### 接口签名
```
作用：防止CSRF攻击
包含：appId + timestamp + sign
时效：5分钟内有效
```

### 加密算法选择
```
对称加密：AES（大量数据）
非对称加密：RSA（少量数据）
哈希：SHA256（完整性校验）
注意：Base64不是加密算法
```

## 七、易错点速记

### 1. @State 限制
```
只能装饰：简单类型 + @Observed装饰的类
不能装饰：普通类、数组
```

### 2. @Prop vs @Link
```
@Prop：单向拷贝（子组件内部副本）
@Link：双向绑定（引用传递）
```

### 3. @Observed 作用域
```
只装饰当前类
嵌套对象必须单独装饰
```

### 4. 迁移数据量
```
KB级别
大数据用分布式数据库中转
```

### 5. 分布式数据库一致性
```
最终一致（非强一致）
```
