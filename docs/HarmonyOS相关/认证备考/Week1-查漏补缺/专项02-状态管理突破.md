## 一、状态装饰器概述

### 1.1 装饰器家族

| 装饰器 | 用途 | 数据流 | 共享范围 |
|--------|------|--------|---------|
| @State | 组件内私有状态 | - | 否 |
| @Prop | 父到子单向传递 | 拷贝 | 否 |
| @Link | 父到子双向绑定 | 引用 | 否 |
| @Provide | 祖先向后代提供 | - | 是 |
| @Consume | 响应 @Provide | - | 是 |
| @StorageLink | AppStorage 双向 | 引用 | 是 |
| @ObjectLink | 对象引用观测 | 引用 | 是 |

## 二、@State / @Prop / @Link 深度对比

### 2.1 核心区别

| 特性 | @State | @Prop | @Link |
|------|--------|-------|-------|
| 数据来源 | 组件内部初始化 | 父组件传入 | 父组件传入 |
| 数据流向 | 单向（组件内部） | 单向（父→子） | 双向（父↔子） |
| 传递方式 | - | 值拷贝 | 引用传递 |
| 变化感知 | 自身变化 | 父变化时更新 | 自身和父变化都感知 |
| 适用场景 | 组件私有状态 | 配置参数 | 双向绑定状态 |

### 2.2 代码示例

```typescript
// 父组件
@Component
struct Parent {
  @State count: number = 0           // 私有状态
  @State title: string = "Hello"    // 私有状态
  @Link userName: string            // 双向绑定，需要初始化

  build() {
    Column() {
      // @State - 单向传递值
      ChildState({ count: this.count, title: this.title })

      // @Link - 双向绑定，传递引用
      ChildLink({ userName: $userName })

      // 点击改变 @State
      Button(`Count: ${this.count}`).onClick(() => {
        this.count++
      })
    }
  }
}

// 子组件 - @State 接收
@Component
struct ChildState {
  @Prop count: number    // 单向，父组件 count 变化会更新
  @Prop title: string

  build() {
    Text(`Count: ${this.count}, Title: ${this.title}`)
  }
}

// 子组件 - @Link 接收
@Component
struct ChildLink {
  @Link userName: string  // 双向，修改会同步到父组件

  build() {
    Column() {
      Text(`UserName: ${this.userName}`)

      Button('Change Name').onClick(() => {
        this.userName = "New Name"  // 会同步到父组件
      })
    }
  }
}
```

### 2.3 常见误区

1. **@Prop 是拷贝**：子组件修改不会影响父组件
2. **@Link 是引用**：子组件修改会影响父组件
3. **@State 不能直接传递给孙子**：需要通过 @Prop 或 @Link

## 三、@Observed / @ObjectLink 原理分析

### 3.1 为什么需要 @Observed

@State 等装饰器只能观测基本类型和 Array。当对象属性变化时，无法触发 UI 更新。

```typescript
// @State 无法观测到 user.name 的变化
@State user: User = { name: "Tom", age: 20 }

// 下面修改不会触发 UI 更新
this.user.name = "Jerry"  // ❌ UI 不会刷新
```

### 3.2 @Observed 装饰器

@Observed 标记一个类为**可观测类**，当其属性变化时会通知框架。

```typescript
@Observed
class User {
  name: string
  age: number
  address: Address  // 嵌套对象也需要 @Observed
}

@Observed
class Address {
  city: string
  street: string
}
```

### 3.3 @ObjectLink 装饰器

@ObjectLink 用于在子组件中引用 @Observed 装饰的对象。

```typescript
@Component
struct ChildComponent {
  @ObjectLink user: User  // 必须是 @Observed 类的实例

  build() {
    Column() {
      Text(`Name: ${this.user.name}`)
      Text(`City: ${this.user.address.city}`)
    }
  }
}

// 父组件
@Observed
class User {
  name: string
  address: Address
}

@Observed
class Address {
  city: string
}

@Component
struct Parent {
  @State user: User = new User()

  build() {
    ChildComponent({ user: this.user })
  }
}
```

### 3.4 原理分析

```
@Observed 类实例
     ↓
创建响应式代理对象（Proxy）
     ↓
属性赋值时触发 set
     ↓
通知框架数据变化
     ↓
UI 重新渲染
```

**关键点**：
1. @Observed 类的属性也必须是 @Observed 类（嵌套对象）
2. @ObjectLink 必须配合 @Observed 使用
3. @ObjectLink 不能单独使用

### 3.5 常见问题

**Q: @ObservedV2 和 @Observed 有什么区别？**
- @ObservedV2 是较新版本，性能更好
- @ObservedV2 需要配合 @Trace 使用

**Q: 对象数组如何观测？**
```typescript
@Observed
class User {
  name: string
}

@State users: User[] = []

// 修改数组中某个对象的属性
this.users[0].name = "New Name"  // 需要 @Observed 才能触发更新
```

## 四、@Provide / @Consume 深度理解

### 4.1 基本用法

@Provide 和 @Consume 实现跨层级数据共享，避免层层传递。

```typescript
@Component
struct GrandParent {
  @Provide("user") user: User = new User()

  build() {
    Parent()
  }
}

@Component
struct Parent {
  // 消费，不初始化
  @Consume("user") user: User

  build() {
    Child()
  }
}

@Component
struct Child {
  // 继续消费
  @Consume("user") user: User

  build() {
    Text(this.user.name)
  }
}
```

### 4.2 与 @StorageLink 的区别

| 特性 | @Provide/@Consume | @StorageLink |
|------|------------------|--------------|
| 作用域 | 组件树内 | 全应用 |
| 持久化 | 否 | 是（AppStorage） |
| 跨设备 | 否 | 可通过分布式存储 |

## 五、项目中的使用场景分析

### 5.1 ViewModel + @State 模式

项目中使用了 MVVM 架构：

```typescript
// ViewModel（继承 AppStorage）
class ArticleListVM extends ViewModel {
  @State articles: Article[] = []
  @State isLoading: boolean = false

  // 业务方法
  async fetchArticles() {
    this.isLoading = true
    // ...
    this.isLoading = false
  }
}
```

### 5.2 @Observed 对象场景

在 `ObservedV2TestPage` 中的使用：

```typescript
@ObservedV2
class Article {
  @Trace id: string
  @Trace title: string
  @Trace author: Author  // 嵌套也需要 @Trace
}

@ObservedV2
class Author {
  @Trace name: string
}
```

### 5.3 常见设计模式

1. **本地状态用 @State**：组件私有
2. **配置参数用 @Prop**：只读配置
3. **双向绑定用 @Link**：表单等
4. **跨层级共享用 @Provide/@Consume**：主题、语言等
5. **持久化用 @StorageLink**：用户偏好设置

## 六、自问自答

### Q1: @State 和 @Link 都可以修改值，有什么区别？

**A:**
- @State 修改只影响当前组件
- @Link 修改会同步到父组件（双向绑定）
- @State 用于组件内部状态，@Link 用于组件间状态同步

### Q2: @Prop 和 @Link 都从父组件获取数据，区别是什么？

**A:**
- @Prop 是**拷贝**：子组件修改不影响父组件
- @Link 是**引用**：子组件修改会影响父组件
- @Prop 适合只读数据，@Link 适合双向同步数据

### Q3: @Observed 类的嵌套对象需要额外处理吗？

**A:**
- 是的，嵌套对象也需要 @Observed 装饰
- 否则修改嵌套对象的属性不会触发 UI 更新
- @ObservedV2 版本使用 @Trace 装饰嵌套属性

### Q4: 什么时候用 @Provide/@Consume 而不是 @Link？

**A:**
- @Provide/@Consume 用于**跨多层组件**共享数据
- @Link 通常用于父子组件之间
- 示例：主题配置需要在多个层级组件中使用

### Q5: @ObjectLink 和 @Link 都能实现双向，有什么区别？

**A:**
- @Link 用于基本类型和 Array
- @ObjectLink 用于 @Observed 装饰的类对象
- @ObjectLink 专门解决对象属性观测问题

## 八、状态管理决策树

```
状态属于哪个范围？
├── 组件私有 → @State
├── 父到子单向，只读 → @Prop
├── 父到子双向同步 → @Link
├── 多层组件共享，不持久化 → @Provide/@Consume
├── 多层组件共享，要持久化 → @StorageLink
└── 对象属性观测 → @Observed + @ObjectLink
```
