### 2. 跨设备迁移（高频考点）

#### 迁移 vs 流转

| 特性 | 跨设备迁移 | 流转(Continuation) |
|------|------------|---------------------|
| UI状态 | 完整迁移 | 不迁移UI |
| 数据量 | KB级别 | 无限制 |
| 适用场景 | 文档编辑、视频播放 | 后台任务 |
| 实现方式 | onContinue | continuationManager |

#### 迁移流程

```typescript
// 1. 迁移开始回调
onContinue(wantParam: Record<string, Object>): boolean {
  // 打包迁移数据
  const userData = {
    articleId: this.currentArticleId,
    readProgress: this.scrollOffset,
    timestamp: Date.now()
  }
  wantParam['userData'] = JSON.stringify(userData)
  return true
}

// 2. 迁移恢复（在目标设备上）
onContinue(wantParam: Record<string, Object>): void {
  const userData = JSON.parse(wantParam['userData'] as string)
  this.articleId = userData.articleId
  this.scrollOffset = userData.readProgress
  this.loadArticle()
}
```

### 4. 分布式数据库

#### 与本地数据库对比

| 特性 | 本地数据库 | 分布式数据库 |
|------|------------|--------------|
| 数据范围 | 单设备 | 多设备同步 |
| 同步方式 | 无 | 自动/手动同步 |
| 数据量 | 无限制 | 受限于设备存储 |
| 一致性 | 强一致 | 最终一致 |

```typescript

// 创建分布式KVStore
const kvManager = distributedKVStore.createKVManager(config)

  createIfMissing: true,
  kvStoreType: distributedKVStore.KVStoreType.SINGLE_VERSION
})

// 同步数据
await kvStore.sync('user_001', distributedKVStore.SyncMode.PUSH_ONLY)
```

### 5. 高频错题

#### 错题1
**题目**: 跨设备迁移的数据量限制是？
- A. 无限制
- B. KB级别
- C. MB级别
- D. GB级别

**正确答案**: B
**解析**: 跨设备迁移使用 WantAgent 传递数据，数据量限制在 KB 级别。大数据需要通过分布式数据库中转。

#### 错题2
**题目**: 迁移和流转的主要区别是？
- A. 迁移迁移UI，流转不迁移UI
- B. 流转迁移UI，迁移不迁移UI
- C. 两者都迁移UI
- D. 两者都不迁移UI

**正确答案**: A
**解析**: 迁移（continuation）会迁移完整的UI状态和用户数据，流转（TaskFlow）只流转任务，不迁移UI。

## 二、安全高频考点

### 1. 权限体系（核心重点）

#### HarmonyOS 权限分类

| 权限等级 | 示例 | 申请方式 |
|----------|------|----------|
| Normal | 通知、网络访问 | 静态声明 |
| Restricted | 位置、相机 | 静态声明 + 运行时申请 |
| Grantable | 读取通讯录 | 用户授权 |
| System | 系统设置 | 系统应用专用 |

#### 权限申请流程

```typescript
// 1. 静态声明（module.json5）
"requestPermissions": [
  {
    "name": "ohos.permission.INTERNET"
  },
  {
    "name": "ohos.permission.GET_NETWORK_INFO"
  }
]

// 2. 运行时检查
import abilityAccessCtrl from '@ohos.abilityAccessCtrl'

async function checkPermission(permission: string): Promise<boolean> {
  const atManager = abilityAccessCtrl.createAtManager()
  const tokenId = await atManager.requestPermissions(context, [permission])
  return tokenId === 0
}

// 3. 权限被拒绝处理
if (!hasPermission) {
  // 引导用户去设置页面开启
  canRequest ? atManager.requestPermissions() : atManager.requestPermissionOnSetting()
}
```

### 2. 数据安全

#### 敏感数据保护

| 数据类型 | 保护方式 | 实现 |
|----------|----------|------|
| 用户密码 | 加密存储 | CryptoUtil |
| Token | AppStorage | @StorageLink |
| 签名 | 拦截器 | SignInterceptor |
| 通信 | HTTPS | TLS加密 |

```typescript
// 签名拦截器
class SignInterceptor implements Interceptor {
  intercept(context: Context, request: Request): Promise<Request> {
    const token = AppStorage.get<string>('token')
    const timestamp = Date.now().toString()
    const sign = CryptoUtil.sha256(token + timestamp)

    request.headers['X-Sign'] = sign
    request.headers['X-Timestamp'] = timestamp
    return Promise.resolve(request)
  }
}
```

#### 加密与解密

```typescript
import cryptoFramework from '@ohos.cryptoFramework'

// AES加密
async function aesEncrypt(data: string, key: string): Promise<string> {
  const cipher = cryptoFramework.createCipher('AES|GCM|PKCS7')
  await cipher.init(cryptoFramework.CryptoMode.ENCRYPT_MODE, key)
  const encrypted = await cipher.doFinal(data)
  return bufferToBase64(encrypted)
}

// SHA256哈希
async function sha256(data: string): Promise<string> {
  const hasher = cryptoFramework.createMd('SHA256')
  const hash = await hasher.update(data)
  return bufferToHex(hash.digest())
}
```

### 3. 接口安全

#### OWASP Top 10 安全实践

| 风险 | 防护措施 |
|------|----------|
| SQL注入 | 参数化查询 |
| XSS | 输入输出编码 |
| CSRF | Token验证 |
| 接口签名 | SignInterceptor |
| 敏感数据 | 加密存储 |

#### 安全设计模式

```typescript
// 1. 接口签名方案
interface SignConfig {
  appId: string
  appSecret: string
  timestamp: number
  signType: 'MD5' | 'SHA256'
}

// 2. 签名生成
function generateSign(config: SignConfig): string {
  const { appId, appSecret, timestamp, signType } = config
  const data = `${appId}${appSecret}${timestamp}`

  if (signType === 'SHA256') {
    return sha256(data)
  }
  return md5(data)
}

// 3. 签名验证
function verifySign(request: Request, sign: string): boolean {
  const timestamp = request.headers['X-Timestamp']
  if (Date.now() - timestamp > 5 * 60 * 1000) {
    return false  // 5分钟内有效
  }
  return generateSign({ ...getConfig(), timestamp }) === sign
}
```

### 4. 安全错题

#### 错题1
**题目**: 以下哪个权限等级需要用户动态授权？
- A. Normal
- B. Restricted
- C. Grantable
- D. System

**正确答案**: C
**解析**: Grantable 级别的权限需要用户在运行时明确授权，如读取通讯录等敏感权限。

#### 错题2
**题目**: 接口签名可以防止以下哪种攻击？
- A. XSS
- B. CSRF
- C. SQL注入
- D. DDOS

**正确答案**: B
**解析**: 接口签名通过验证请求的完整性和时效性，可以有效防止CSRF攻击。

#### 错题3
**题目**: 分布式数据库和本地数据库的主要区别是？
- A. 分布式数据库更快
- B. 分布式数据库支持多设备同步
- C. 分布式数据库存储空间更大
- D. 分布式数据库更安全

**正确答案**: B
**解析**: 分布式数据库的核心特性是支持多设备间的数据同步，而不仅仅是性能或存储空间的差异。

## 三、综合场景题

### 场景1: 设计一个安全的收藏同步功能

**需求**:
1. 用户收藏在本地加密存储
2. 跨设备同步需要安全验证
3. 离线时缓存，同步时加密传输

**参考方案**:

```typescript
class SecureCollectSync {
  // 1. 本地加密存储
  async saveCollect(article: Article) {
    const encrypted = await CryptoUtil.aesEncrypt(
      JSON.stringify(article),
      this.getEncryptionKey()
    )
    await DistributedStore.set('collect_' + article.id, encrypted)
  }

  // 2. 跨设备同步
  async syncToDevice(targetDeviceId: string) {
    const token = AppStorage.get<string>('token')
    const timestamp = Date.now().toString()
    const sign = CryptoUtil.sha256(token + timestamp)

    // 通过分布式数据库同步
    await DistributedKVStore.sync({
      deviceId: targetDeviceId,
      sign,
      timestamp
    })
  }

  // 3. 安全验证
  async verifyAndSync(request: SyncRequest): Promise<boolean> {
    // 验证签名
    const isValid = this.verifySign(request)
    if (!isValid) return false

    // 验证token时效性
    const isTokenValid = await this.validateToken(request.token)
    if (!isTokenValid) return false

    // 执行同步
    return this.doSync(request)
  }
}
```
