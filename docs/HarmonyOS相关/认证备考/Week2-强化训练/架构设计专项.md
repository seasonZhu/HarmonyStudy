## 一、架构设计高频考点

### 1. MVVM 架构模式（核心重点）

#### MVVM 架构分层

```
┌─────────────────────────────────────┐
│            View (页面)              │
│  - 使用 ArkUI 声明式UI             │
│  - 仅负责UI渲染和用户交互           │
│  - 通过数据绑定获取 ViewModel 数据  │
└─────────────────────────────────────┘
                    ↕ 数据绑定
┌─────────────────────────────────────┐
│          ViewModel                  │
│  - 继承 AppStorage/v2/LocalStorage  │
│  - 管理页面状态和业务逻辑           │
│  - 调用 Model 层处理数据            │
│  - 不直接操作 UI                    │
└─────────────────────────────────────┘
                    ↕ 调用
┌─────────────────────────────────────┐
│            Model (模型)             │
│  - 数据模型定义                     │
│  - 网络请求封装                     │
│  - 本地数据存储                     │
│  - 业务逻辑处理                     │
└─────────────────────────────────────┘
```

#### 项目中的 MVVM 实践

```typescript
// Model 层 - 数据模型
class Article {
  id: number
  title: string
  author: string
}

// Model 层 - 网络请求
class ArticleModel {
  getArticle(id: number): Promise<Article> {
    return httpClient.get(`/article/${id}`)
  }
}

// ViewModel 层 - 状态管理
class ArticleViewModel {
  @State article: Article = new Article()

  loadArticle(id: number) {
    new ArticleModel().getArticle(id).then(article => {
      this.article = article
    })
  }
}

// View 层 - 页面
@Entry
@Component
struct ArticlePage {
  @State viewModel = new ArticleViewModel()

  build() {
    Column() {
      Text(this.viewModel.article.title)
    }
  }
}
```

### 3. 模块化设计

#### 模块化原则

| 原则 | 说明 | 示例 |
|------|------|------|
| 单一职责 | 每个模块只负责一件事 | 登录模块、搜索模块 |
| 低耦合 | 模块间依赖最小化 | 通过接口通信 |
| 高内聚 | 相关功能放在一起 | 相关页面和组件放同一模块 |
| 可复用 | 模块可被多个页面使用 | BannerView、ArticleMetaRow |

#### 项目模块划分

```
entry/src/main/ets/
├── pages/           # 页面（TabScaffold、Home、Login）

├── router/          # 路由管理
├── utils/           # 工具类

```

### 4. 路由管理

#### 路由守卫模式

```typescript
// 路由守卫类型
enum GuardType {
  LOGIN = 'login',      // 登录拦截
  AUTH = 'auth',        // 权限拦截
  SUBSCRIBE = 'subscribe'  // 订阅拦截
}

// 守卫结果
class GuardResult {
  pass: boolean
  redirect?: string
}

// 路由守卫接口
interface RouteGuard {
  guardType: GuardType
  check(context: Context): Promise<GuardResult>
}

// 登录守卫实现
class LoginGuard implements RouteGuard {
  guardType = GuardType.LOGIN

  async check(context: Context): Promise<GuardResult> {
    const isLoggedIn = AccountManager.shared().isLoggedIn()
    return {
      pass: isLoggedIn,
      redirect: isLoggedIn ? undefined : PagesConstant.Login
    }
  }
}
```

#### 路由守卫管理

```typescript
class GuardManager {
  private guards: RouteGuard[] = []

  registerGuard(guard: RouteGuard) {
    this.guards.push(guard)
  }

  async checkAll(context: Context): Promise<GuardResult> {
    for (const guard of this.guards) {
      const result = await guard.check(context)
      if (!result.pass) {
        return result
      }
    }
    return { pass: true }
  }
}
```

### 题目1: 设计一个登录模块

**要求**:
1. 支持自动登录
2. 支持多设备同步
3. 支持登录失效处理

**参考方案**:

```typescript
// 1. 登录状态管理
class LoginState {
  // 自动登录检查
  async autoLogin(): Promise<boolean> {
    const token = AppStorage.get<string>('token')
    if (!token) return false

    // 验证token有效性
    const isValid = await this.validateToken(token)
    if (isValid) {
      // 恢复登录状态
      const userInfo = await this.getUserInfo(token)
      AccountManager.shared().setLoginModel(userInfo)
      return true
    }
    return false
  }

  // 登录
  async login(username: string, password: string): Promise<LoginResult> {
    const result = await LoginModel.login(username, password)
    if (result.errorCode === 0) {
      // 保存token
      AppStorage.setOrCreate('token', result.data.token)
      // 同步到其他设备
      this.syncLoginState(result.data)
      // 设置登录状态
      AccountManager.shared().loginModel = result.data
    }
    return result
  }

  // 登录失效处理
  handleLoginExpired() {
    // 清除本地状态
    AppStorage.delete('token')
    AccountManager.shared().clear()
    // 跳转到登录页
    Router.replaceNamedRoute(PagesConstant.Login)
  }
}
```

```typescript
// 1. 环境配置
enum Environment {
  DEV = 'https://dev-api.example.com',
  TEST = 'https://test-api.example.com',
  PROD = 'https://api.example.com'
}

// 2. 环境管理器
class EnvironmentManager {
  private current: Environment = Environment.DEV

  setEnvironment(env: Environment) {
    this.current = env
  }

  getBaseUrl(): string {
    return this.current
  }
}

// 3. 缓存策略
interface CacheStrategy {
  get<T>(key: string): T | null
  set<T>(key: string, value: T, ttl: number): void
  delete(key: string): void
}

// 4. 错误重试机制
class RetryInterceptor {
  constructor(
    private maxRetries: number = 3,
    private retryDelay: number = 1000
  ) {}

  async intercept(request: Request, next: Next): Promise<Response> {
    let lastError: Error

    for (let i = 0; i < this.maxRetries; i++) {
      try {
        return await next(request)
      } catch (error) {
        lastError = error
        if (!this.shouldRetry(error)) {
          throw error
        }
        await this.delay(this.retryDelay * (i + 1))
      }
    }

    throw lastError
  }

  private shouldRetry(error: Error): boolean {
    // 网络错误、超时等可重试
    return error.code === 'NETWORK_ERROR' || error.code === 'TIMEOUT'
  }
}
```

### 题目3: 设计一个列表页面架构

**要求**:
1. 下拉刷新
2. 上拉加载更多
3. 列表性能优化

**参考方案**:

```typescript
// 1. 列表数据源（LazyForEach）
class ArticleDataSource implements DataSource {
  private data: Article[] = []

  totalCount(): number {
    return this.data.length
  }

  getData(index: number): Article {
    return this.data[index]
  }

  addData(articles: Article[]) {
    this.data.push(...articles)
    this.notifyDataAdd(this.data.length - articles.length)
  }

  refreshData(articles: Article[]) {
    this.data = articles
    this.notifyDataReload()
  }
}

// 2. ViewModel
class ListViewModel {
  @State dataSource: ArticleDataSource = new ArticleDataSource()
  @State isRefreshing: boolean = false
  @State hasMore: boolean = true

  private pageNum: number = 1

  async refresh() {
    this.isRefreshing = true
    this.pageNum = 1
    const articles = await this.loadArticle(this.pageNum)
    this.dataSource.refreshData(articles)
    this.hasMore = articles.length >= PAGE_SIZE
    this.isRefreshing = false
  }

  async loadMore() {
    if (!this.hasMore) return
    this.pageNum++
    const articles = await this.loadArticle(this.pageNum)
    this.dataSource.addData(articles)
    this.hasMore = articles.length >= PAGE_SIZE
  }
}

// 3. View
@Entry
@Component
struct ArticleListPage {
  @State viewModel = new ListViewModel()

  build() {
    List() {
      LazyForEach(this.viewModel.dataSource, (article: Article) => {
        ListItem() {
          ArticleItem({ article: article })
        }
      }, (article: Article) => article.id.toString())
    }
    .onScrollIndex((startIndex: number, endIndex: number) => {
      // 加载更多逻辑
      if (endIndex >= this.viewModel.dataSource.totalCount() - 5) {
        this.viewModel.loadMore()
      }
    })
    .onRefreshing(async () => {
      await this.viewModel.refresh()
    })
  }
}
```

## 三、常见架构模式总结

### 1. 组件化 vs 模块化

| 维度 | 组件化 | 模块化 |
|------|--------|--------|
| 粒度 | UI组件 | 功能模块 |
| 复用 | UI复用 | 功能复用 |
| 独立性 | 组件独立 | 模块可独立运行 |
| 通信 | 属性/事件 | 接口调用 |

### 2. 集中式 vs 分布式状态管理

| 模式 | 优点 | 缺点 | 适用场景 |
|------|------|------|----------|
| 集中式（ViewModel） | 状态可追溯 | 复杂度高 | 中大型应用 |
| 分布式（@Provide/@Consume） | 简单直接 | 状态分散 | 小型应用 |

### 3. 路由管理方案

| 方案 | 优点 | 缺点 |
|------|------|------|
| 基于配置 | 统一管理 | 灵活性差 |
| 基于注解 | 声明式 | 复杂度高 |
| 混合方案 | 灵活 | 学习成本 |

## 四、错题分析

### 题目1
**题目**: MVVM 架构中，ViewModel 的主要作用是？
- A. 直接操作数据库
- B. 管理页面状态和处理业务逻辑
- C. 渲染UI
- D. 处理用户输入

**正确答案**: B
**解析**: ViewModel 负责管理页面状态和处理业务逻辑，通过数据绑定与 View 通信，不直接操作数据库或渲染UI。

---

### 题目2
**题目**: 以下关于模块化的说法正确的是？
- A. 模块之间应该高耦合
- B. 每个模块应该只负责一个功能
- C. 模块化会增加代码复杂度
- D. 模块化不利于团队协作

**正确答案**: B
**解析**: 模块化遵循单一职责原则，每个模块只负责一个功能，模块间低耦合，有利于团队协作和代码维护。

**题目**: 路由守卫的主要作用是？
- A. 优化路由性能
- B. 统一处理路由跳转前的逻辑
- C. 管理路由表
- D. 处理路由动画
